## اجرای کنترل‌شده

در workflow ثبت‌شدهٔ `android-release.yml`، ورودی `repair_delivery=true` فقط job بررسی فایل را اجرا می‌کند، نه آموزش مدل/ساخت APK/تست‌های طولانی اندروید را. حالت عادی workflow بدون این ورودی تغییر نمی‌کند.

`tools/verify-release-delivery.py` وضعیت ساخت و metadata را با منبع مرجع تطبیق می‌دهد، خود ZIP را دریافت می‌کند، اندازه/SHA256 و CRC آن و APK داخلی را بررسی می‌کند و سپس `apksigner`، گواهی قبلی و package/version را کنترل می‌کند. آزمون‌های این ابزار:

```sh
python3 -m unittest discover -s tools/tests -p 'test_release_delivery.py' -v
```

job فقط مجوزهای `contents: read` و `actions: read` دارد و نمی‌تواند Release یا فایل مخزن منتشر کند. artifact جایگزین شامل APK بدون ZIP تو‌در‌تو و گزارش بررسی است؛ فشرده‌سازی ثانویه غیرفعال است. خود سرویس artifact همچنان ظرف ZIP می‌سازد.

## انتقال خصوصی اختیاری

ورودی `delivery_callback` فقط برای دریافت یک‌باره در فضای کاری همان نشست است. URL فقط HTTPS و میزبان پیش‌نمایش موقت workspace با مسیر nonce پذیرفته می‌شود؛ redirect دنبال نمی‌شود. نشانی موقت در log ماسک می‌شود و هیچ هدر احراز هویت GitHub به آن ارسال نمی‌شود.

ZIP در بخش‌های محدود فرستاده می‌شود؛ گیرنده دوباره SHA/CRC فایل و APK را بررسی می‌کند. گیرندهٔ این نشست فقط POST یک‌باره و صفحهٔ وضعیت دارد، نه مسیر دانلود عمومی فایل. APK نهایی از فایل‌نمای خصوصی گفتگو ارائه می‌شود و سرور موقت بعد از انتقال متوقف می‌شود. اگر انتقال یا بررسی موفق نشود، نباید APK محلی یا سلامت فایل کاربر ادعا شود.

اگر فایل مرجع منقضی یا عوض شد، کنترل‌ها باید شکست بخورند؛ به فایل/نسخهٔ دیگری بی‌صدا رجوع نمی‌شود.
